A5K — Technical Specifications

Clocks, memory, processors, bandwidth and the limits they impose

1 November 2026  ·  Companion to the design proposition  ·  Figures are targets, not measurements

Design study. Nothing described here has been built or measured. Clock rates are synthesis estimates for the named device families; bandwidth figures are arithmetic from bus width and data rate; processor core counts are what the logic can hold, not what the software needs.

1. What this is — and what it is not

This document specifies A5K (C+), the frozen reference model. It is a PCIe add-in card. It is not a computer, not a single-board machine, and not a replacement for a motherboard. It has no CPU, no boot firmware and no operating system of its own. It is a display and timing device that plugs into a host PC, in the same mechanical and electrical class as a graphics card.

The host supplies the CPU, the memory the OS runs in, the storage and the operating system. The card supplies the chipset, its own Chip RAM and its own display output. Unplug the host and the card is a board with a power LED.

The small RISC-V core on the card is not an application processor. It is housekeeping — timers, GPIO, the SD card and interrupt aggregation — running bare-metal firmware at 50–150 MHz, with no MMU and no loader. Applications and drivers run on the host, compiled for the host's architecture. The card contributes the chipset, not the CPU.

It cannot be plugged into a Commodore Amiga. The A2000 has Zorro II, the A3000 and A4000 have Zorro III, the A1200 has a trapdoor and PCMCIA. None of them has PCIe, and no bridge exists that would make a modern card enumerate on a 68k bus.

2. Host requirements

Today the card requires an x86-64 PC. Other host architectures are technically possible — the interface is standard PCIe — but they are untested, and some RISC-V boards expose only a single lane.

3. Why ×1 on the reference card, and ×4 on the Studio Pro

The reference card is electrically ×1. The display is fetched from the card's own DDR3L; PCIe carries Copper lists, register writes and the occasional frame readback. Half a gigabyte per second is already an order of magnitude more than control traffic needs. The Studio Pro uses ×4 because two pipelines and a capture stream want real bandwidth.

The lane budget decides it. An Artix-7 100T has exactly four GTP transceivers, and 4K60 output consumes three of them for HDMI. One is left, and that is the PCIe link: ×1. The Studio Pro moves to a Kintex-7 325T, where sixteen transceivers allow two 4K60 transmitters and ×4 to the host.

A ×1 card still fits any slot. A ×1 card seats in ×1, ×2, ×4, ×8 and ×16 connectors, including the ×4 slot a desktop usually has free. The physical connector on the reference card is ×4-length for mechanical stability; the link is ×1.

Why DDR3L, and not DDR5. The target families cannot drive DDR5 at all — it needs an UltraScale+ or Versal part, at roughly ten times the FPGA cost. DDR3L is still in production for industrial and networking equipment, is stocked by every distributor, and costs about $7 per 512 MB. A 32-bit DDR3L bus supplies 6.4 GB/s, which is more than the slot table can consume. DDR5 would solve a bandwidth problem this machine does not have, at a price it cannot pay.

Upgrade path. 1 GB to 2 GB is a device swap in the same footprint — 4 Gb parts for 8 Gb. 2 GB to 4 GB needs two ranks and rank support in the memory controller. Beyond 4 GiB the obstacle is not the memory but the pointer width: the 64-bit variant widens both, and moves to DDR4.

ECC is the more valuable upgrade for instrumentation work than capacity: on a 32-bit bus it means 40 bits and five x8 devices instead of two x16. DDR3 tops out at 8 Gb per device, which is why 4 GB is the wall for the 32-bit design. Host memory is reached by DMA over PCIe and is not limited by the card.

The on-card core is a supervisor, not an engine. It runs CIA timers, GPIO and interrupt aggregation. Whether it runs at 50 MHz or 667 MHz changes almost nothing, because it does not draw pixels — the Copper, blitter and planes do. Spending fabric on clock speed here is spending it in the wrong place. The heavy work belongs on the host, on the other side of PCIe.

7. Bandwidth budget at 4K60

3840 × 2160 = 8.29 megapixels. The 32-bit DDR3L bus supplies 6.4 GB/s, and the slot table must also fit the Copper, the blitter and audio into the same schedule.

This is the quiet argument for planar graphics: at 4K60, eight bitplanes cost a twelfth of what eight ARGB planes cost. The Amiga's bitmap format was a bandwidth strategy, not a limitation.

8. Parallelism

Table S8. What runs simultaneously, and what does not.
UnitCountNature
Copper1One sequencer, one instruction per tick; parallel with everything else, serial within itself
Blitter1One operation at a time, by design
Planes8 (16 optional)Fetched in parallel each line
Audio channels4–8Independent DMA streams
Slot table1Fixed schedule; every cycle allocated before the frame
Host coresunboundedOutside the card, over PCIe

Parallelism here is spatial, not threaded. Roughly twenty independent units run at once because each does one thing forever at a fixed rate — not because anything is scheduled. Adding CPU cores does not add throughput; it adds contention on the same memory. The bound is bandwidth: at 6.4 GB/s, the display pipeline is the budget, and the slot table is the ledger.

What would have to change for more. More planes at 4K means a wider memory bus before it means more logic. A faster on-card CPU means a hard core, not a bigger soft one. More host bandwidth means Gen3 or Gen4, which means an Artix-7 with GTP or a larger part. Each is a different board, not a different setting.
